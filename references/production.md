# 实测、配音与自动剪辑

只在 `selected`、`demo_verified`、`script_ready` 或 `audio_ready` 阶段读取。

## 用户素材优先

用户只需提供一个 `user-assets/` 文件夹，优先内容是：

- 一段 15–30 秒原始核心操作录屏，开头和结尾各保留约 2 秒；
- 或至少 3 张原图：使用前、操作过程、最终结果；
- 一段很短的真实体验：版本/平台、解决的问题、实际限制。

不要要求用户加字幕、转场、音乐或竖屏裁切。先检查隐私和画面可用性；不足时由 Codex 补充官方素材或自动实测截图。不要把用户素材声明为 Codex 独立实测。

## 核心演示通过条件

- 使用的是官方项目和可识别版本；
- 画面能证明准备讲述的功能；
- 结果与官方说明一致；
- 不暴露凭据或私人数据；
- 竖屏裁切后仍然可读。

通过后把证据路径、来源类型和限制写入 `episode.json`，推进到 `demo_verified`。

## 口播与配音

- 口播围绕一个痛点和一个演示，不写功能清单。
- 开头 0–3 秒先给结果或冲突；随后解释项目、操作、真实限制与适合人群。
- 不虚构功能、免费范围、模型能力或安装体验。
- 结尾自然加入关注引导，并确保实际音频和字幕均包含它。
- 默认用剪映专业版“曼波讲故事”文本朗读；生成后以实际音频为时间轴。不要根据文字长度猜时长。
- 执行剪映操作前加载当前可用的 Windows computer-use Skill，遵守其中的视觉核验与停止条件。
- 保存脚本、实际音频和实际转录文本，并依次推进 `script_ready`、`audio_ready`。

## 模板化剪辑

1. 本期没有视觉规范时，把 `assets/default-design.md` 复制为本期 `DESIGN.md`；有参考视频时只覆盖明确的视觉选择，保留抖音安全区。
2. 优先使用可复现的代码渲染。HyperFrames 可用时，先加载其 composition 与 CLI skill，读取本期 `DESIGN.md`，按实际音频建立分镜。
3. 先输出快速草稿，运行 lint/validate/inspect，检查关键英雄帧，再渲染最终版。详细日志写入 `logs/`。
4. 场景优先顺序：真实结果钩子、官方项目身份、核心操作、真实结果/限制、适合人群、CTA。
5. 用户录屏画质不足、遮挡或裁切后不可读时，允许 Codex 在已确认项目范围内自行截图或录制同一核心操作。
6. 同时生成 `1080x1920` 竖封面和 `1440x1080` 4:3 横封面；封面文字必须位于裁切安全区。

完成后记录最终 MP4、封面、脚本、音频、转录和发布文案路径，推进到 `rendered`。
