# 高价值 GitHub 项目筛选

只在 `researching` 或 `awaiting_selection` 阶段读取。

## 先做的检查

1. 读取当前工作区 `AGENTS.md` 和已完成视频清单，先排除重复主题。
2. 优先使用官方仓库、官方网站、官方文档和 GitHub API。记录核实日期、仓库、最新版本、维护状态、支持平台和下载入口。
3. 候选阶段不安装全部项目，不读取大量无关 issue，也不因 Stars 高就默认推荐。

## 高价值门槛

项目必须同时满足大部分条件：

- 解决 Codex、Claude Code 或 AI 编程用户的真实问题；
- 普通技术观众能在一句话内理解用途；
- 前三秒可展示明确痛点或结果；
- 核心操作可以在 Windows 上低成本演示；
- 官方项目仍在维护；
- 费用、账号、网络和安全限制可以准确说明；
- 与已经发布的项目和角度不重复；
- 画面适合竖屏裁切，不依赖大量终端小字。

Stars 只用于证明关注度，在价值相近时作为排序参考。

## 给用户的候选

内部可以研究多个项目，对用户最多展示 3 个，并明确唯一首推。每个候选只写：

- 项目与官方链接；
- 真实痛点；
- 唯一核心演示；
- 前三秒结果；
- Windows/平台和官方下载；
- 主要费用、安全或使用限制；
- 推荐或不首推的原因。

用户一次同时确认“项目 + 痛点 + 核心演示 + 前三秒结果”。确认后才初始化本期目录并进入 `selected`。

## 分层实测

- 用户提供真实录屏、截图和体验说明时优先使用；先运行 `scripts/inspect_user_assets.py`。
- 素材能清楚证明核心功能时，不重复安装测试，只核实官方版本和事实。
- 素材不足时，只补拍缺失的画面或补测唯一核心功能。
- 两种执行方式都失败、功能与官方描述不符或结果不适合视频展示时，返回 `awaiting_selection`，不继续写稿和配音。
