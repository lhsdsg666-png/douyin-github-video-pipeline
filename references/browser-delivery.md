# 抖音浏览器交付状态机

只在 `qa_passed` 或 `uploading` 阶段读取。网页结构会变化，先检查当前页面，不把这里的定位方式当成永久 DOM。

## 开始条件

- `episode.json` 的 `qa.passed` 为 `true`；
- `publish/publish-payload.json` 已由脚本生成；
- 使用用户已经登录的 Chrome；
- 执行写操作前加载当前可用的 Chrome 控制 Skill，并遵守它的页面读取和交互规则；
- 明确确认 `creator.douyin.com` 和目标账号；
- 浏览器只读取发布载荷，不重新生成标题、文案、标签或文件路径。

账号不匹配、登录失效、验证码、身份验证或风险提示出现时立即停止，不读取 Cookie、Token 或密码。

## 快速操作原则

- 优先使用可访问名称、标签文本、稳定输入框属性和当前页面 DOM；状态不明时才使用局部截图。
- 通过创作者中心可见菜单进入正确的视频投稿页，避免反复直接跳 URL。
- 上传前准备文件选择事件，一次提交最终 MP4；等待页面明确显示上传完成。
- 填写标题、介绍和话题后读取实际字段，确认没有重复正文或失效话题。
- 设置竖封面和 4:3 横封面后读取页面预览或尺寸提示。
- 每个外部提交按钮只点击一次；固定等待不替代页面状态检查。

## 发布前断言

同时确认：

- 上传文件名、时长和最终 MP4一致；
- 标题、介绍、话题与 payload 一致；
- 必要费用说明没有丢失；
- 两种封面均已设置且预览正确；
- 当前账号正确；
- 当前模式与 payload 一致。

任一失败都不点击“暂存离开”或定时提交。记录失败字段并转为 `needs_attention`。

## `draft` 模式

1. 默认执行此模式，不设置定时发布。
2. 点击“暂存离开”一次。
3. 到草稿/内容管理页按本期标题核验草稿存在，并核对封面或时间等可见字段；把可复核证据写入 `browser.evidence`。
4. 只有明确找到草稿且存在证据后才记录 `draft_saved`。页面没有反馈时先核验，禁止再次点击。

## `schedule` 模式

1. payload 必须包含准确的带时区时间，且 `schedule_confirmation` 的指纹与当前 payload 一致。
2. 在第一次可能导致预约公开的点击前，向用户展示最终视频、账号、标题和准确时间；只有用户明确确认才可在状态文件中记录授权。
3. 设置定时时间后读取页面值，确认完全一致，再提交一次。
4. 提交后进入内容管理页核验。区分“审核中”“已提交未来时间”和页面明确显示的“定时发布中”，不能把它们混报；把准确时间和可复核证据写入 `browser.evidence`。
5. 只有明确显示预约成功、正确时间且存在证据后才记录 `scheduled`。

不支持立即公开发布。

## 停止条件

- 同一操作使用两种方法仍失败；
- 上传状态、暂存结果或定时结果不确定；
- 出现同标题草稿但无法判断是否为本期；
- 页面字段被清空、重复或自动改写；
- 话题没有被平台识别；
- 封面、可见范围、发布时间或账号不正确；
- 页面结构变化导致关键控件无法可靠定位。

停止时保存当前页面证据和准确字段，不删除、不重传、不覆盖，转为 `needs_attention`。
